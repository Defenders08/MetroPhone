# WP-ANIMATIONS — анимации Windows Phone и как их делать в MetroPhone

Разбор анимационной системы Windows Phone (Metro motion) с точными параметрами из
исходников Windows Phone Toolkit и маппингом на iOS 6 / iPhone 4 (A4).
Живые демо — в соседнем [MetroPhone-анимации.html](MetroPhone-анимации.html).
В твик пока НИЧЕГО не перенесено — это референс для будущего внедрения.

Источники параметров:
- Официальный архив тулкита: https://github.com/microsoftarchive/WindowsPhoneToolkit
  (Ms-PL). Все числа ниже — из `Transitions/Storyboards/*.xaml`, `Transitions/Transitions/Transitions.cs`,
  `Effects/TurnstileFeatherEffect.cs`.
- Continuum — реализация Бена Калла, лёгшая в основу официальной (Nov 2012):
  https://gist.github.com/bjcull/1345156

## 1. Принципы Metro motion

1. **Два темпа**: «въезд» ≈ 0.35 с с торможением (ExponentialEase EaseOut),
   «выезд» ≈ 0.25 с с разгоном (ExponentialEase EaseIn). Анимация в целом короткая,
   зато фазы асимметричны — быстрый уход, мягкий приход.
2. **ExponentialEase, exponent 6** — фирменная кривая почти всех переходов:
   `y = (1 − 2^(−6t)) / (1 − 2^(−6))` (out) и зеркальная `(2^(6t) − 1) / 63` (in).
   Резкий старт, длинный хвост, **никакого bounce/spring** — это слово Metro.
3. **Перспектива вместо масштаба**: глубина передаётся 3D-поворотами вокруг края
   (шарнира), а не «зумом». Шарнир почти всегда на левом краю.
4. **Стаггер 40–50 мс**: списки/плитки не въезжают разом, а волной по индексу элемента.
5. **Анимировать только видимое**: тулкит сам федерит лишь элементы во вьюпорте
   (`IsOnScreen` в TurnstileFeatherEffect) — у нас то же правило уже выработано
   независимо (комментарий в MPTilesPageView.m:161: 45 анимаций на A4 = рывки).
6. Фейд — «страховочный», не основной: в turnstile-in непрозрачность восстанавливается
   за 10 мс, в turnstile-out исчезает на последних 10 мс. Основную работу делает поворот.

## 2. Переходы страниц (точные параметры)

Общая механика тулкита: `TransitionFrame` прячет старую страницу, ставит проекцию
`PlaneProjection` на новую, крутит сториборд, по завершении всё восстанавливает.
У нас ту же роль сыграют `CABasicAnimation`/`CAKeyframeAnimation` на `layer.transform`.

### 2.1 Turnstile — «вертушка» (фирменный переход WP)

Вращение вокруг вертикальной оси, шарнир **CenterOfRotationX = 0** (левый край),
перспектива встроена в PlaneProjection.

| Фаза | RotationY | Время | Easing | Opacity |
|---|---|---|---|---|
| ForwardIn (страница въезжает «вперёд») | −80° → 0° | 0.35 с | ExpEaseOut exp6 | 0→1 за первые 0.01 с |
| ForwardOut (уезжает «вперёд») | 0° → +50° | 0.25 с | ExpEaseIn exp6 | 1, затем 1→0 за последние 0.01 с |
| BackwardIn (въезжает «назад») | +50° → 0° | 0.35 с | ExpEaseOut exp6 | 0→1 за 0.01 с |
| BackwardOut (уезжает «назад») | 0° → −80° | 0.25 с | ExpEaseIn exp6 | 1→0 в конце |

Источник: `Storyboards/TurnstileForwardIn.xaml` и соседние; `Transitions.cs` ставит
`PlaneProjection { CenterOfRotationX = 0 }`. Логика направления: «вперёд» = новая
страница поднимается из-за левого края; «назад» = зеркально (положительные углы).

### 2.2 TurnstileFeather — тот самый въезд плиток WP8

Тот же поворот, но **по элементам страницы** со стаггером. Из `TurnstileFeatherEffect.cs`:

| Параметр | Значение |
|---|---|
| Углы и длительности | те же, что у Turnstile (350/250/350/250 мс, ±80°/50°) |
| Стаггер | `BeginTime = delay × index`: 40 мс (in), 50 мс (out) на элемент |
| CenterOfRotationX | **−0.2** (шарнир левее плитки — «перьевой» разворот) |
| Easing | ExponentialEase exp6 (out для in-фаз, in для out-фаз) |
| Opacity | in: элемент заранее 0.0, мгновенное восстановление в свой BeginTime; out: зануление в `delay×index + duration` |
| Отбор | только видимые на экране элементы (`TransformToVisual` + отсечение), ListBox/LLS федерятся по-элементно |
| Порядок | attached-свойство `FeatheringIndex`, < 0 — исключить |

Это буквально наш кейс: правило «анимировать только видимые плитки» у нас уже
сформулировано в коде, стаггер к тому же снижает одновременную нагрузку.

### 2.3 Swivel — вращение по горизонтальной оси

| Фаза | RotationX | Время | Easing |
|---|---|---|---|
| ForwardIn | −45° → 0° | 0.35 с | ExpEaseOut exp6 |
| ForwardOut | 0° → +45° | 0.25 с | ExpEaseIn exp6 |
| BackwardIn / BackwardOut | зеркально (+45→0 / 0→−45) | 0.35 / 0.25 | те же |
| FullScreenUp/Down | ±60…90°, центр вращения 0.5 | 0.5–0.7 с | exp6 |

Центр вращения по вертикали — 0.5 (середина), `SwivelForwardIn.xaml`.

### 2.4 Slide — сдвиг с фейдом

`SlideUpFadeIn.xaml`: `TranslateTransform.Y` **200 → 0** + Opacity 0→1, 0.35 с,
оба — ExpEaseOut exp6. Out-фазы: 0.25 с, EaseIn, уход в противоположную сторону
(SlideLeft/Right/Up/Down). Это прямой кандидат на замену нативного push в Настройках
(FIX-PLAN, этап 6: «слайд 0.25 с» — сходится с тулкитом с точностью до темпа).

### 2.5 Rotate и Roll — в плоскости

- **RotateIn90Clockwise**: RotationZ 90° → 0°, 0.25 с, ExpEaseOut **exp1** + фейд
  0→1 SineEase EaseOut. Центр (0.5, 0.5). Out: 0→90°, 0.25 с, EaseIn + фейд.
- **Roll**: RotationZ 0 → 45° (0.3 с: EaseIn exp1 → EaseOut exp6) → 90° (0.6 с),
  центр (0.5, 0.5) — «сверток» на 90° в плоскости. Декоративный, для нас
  малоприменимый.

### 2.6 Continuum — 0.15 с, с «героем»

Реализация Бена Калла (основа официальной). Особенность: отдельный «герой»-элемент
(обычно заголовок страницы) живёт своей жизнью. Всё очень короткое — 0.15 с:

| Фаза | Общий контент | Hero-элемент |
|---|---|---|
| ForwardOut | Y 0→70 + фейд 1→0 (ExpEaseIn exp3) | Y 0→73, X 0→225, фейд в конце |
| ForwardIn | Y 50→0 + фейд 0→1 (exp6) | Y −70→0, X 130→0 (ExpEaseOut exp3) |
| BackwardOut | Y 0→50 + фейд (exp6) | — |
| BackwardIn | фейд 0→1 (exp6) | X −70→0, Y −30→0 |

Идея для нас: hero = заголовок страницы («НАЧАЛО», «настройки»), всё остальное —
короткий сдвиг. Дёшево (только translate/opacity, без 3D), очень «метро».

### 2.7 Флип живой плитки (HubTile) и нажатие (tilt)

- **Flip** (смена контента плитки): XAML-шаблон HubTile в архиве тулкита не найден
  (папка HubTile — только .cs, анимация живёт в теме). По визуалу WP8: поворот вокруг
  Y на 180°, ~0.6–1 с, ease-in-out, обратная сторона пред-повёрнута на 180°
  (preserve-3d). В наших HTML-прототипах уже используется rotateY 180° за 0.6 с —
  выглядит аутентично. Точку менять при желании: продолжительность и всё.
- **Tilt-нажатие** (Start-экран WP8.1): плитка **наклоняется к точке касания**
  (3D-поворот на несколько градусов вокруг точки под пальцем) + чуть уменьшается и
  темнеет; возврат ~0.15–0.2 с. В системных числах Microsoft это не публиковалось —
  рабочие значения: угол ≤ 6°, scale ≈ 0.97, затемнение ≈ 6–8 %, in ≈ 0.1 с, out ≈ 0.2 с.

## 3. Маппинг на iOS 6 (iPhone 4)

### 3.1 API

| Приём WP | Чем делать в iOS 6 |
|---|---|
| PlaneProjection, вращение вокруг Y/X | `CATransform3DMakeRotation` + перспектива `m34 = −1/500…−1/800`; **шарнир = `anchorPoint` слоя** (левый край → `(0, 0.5)`, −20 % → `(−0.2, 0.5)`) с компенсацией `position`, либо обёртка-контейнер |
| ExponentialEase exp6 | `CAMediaTimingFunction` с controlPoints-аппроксимацией (ниже) или точно — `CAKeyframeAnimation` с таблицей значений |
| Storyboard из двух фаз (Roll 0→45→90; фейд на последних 10 мс) | `CAKeyframeAnimation` с `keyTimes` (0 / 0.5 / 1 или 0 / 0.96 / 1) |
| Стаггер `BeginTime = 40 мс × index` | блоковые `[UIView animateWithDuration:delay:options:animations:completion:]` с `delay` по индексу, `UIViewAnimationOptionBeginFromCurrentState` |
| Opacity 0→1 за 0.01 с | просто выставить `alpha = 1` до старта анимации трансформа |

### 3.2 Кривые: точная формула и аппроксимации

ExponentialEase exp6:
- EaseOut: `y = (1 − 2^(−6t)) / 0.984375` — кубическая аппроксимация
  `cubic-bezier(0.17, 0.62, 0.31, 1)`
- EaseIn: `y = (2^(6t) − 1) / 63` — `cubic-bezier(0.69, 0, 0.83, 0.38)`
- exp3 (Continuum): out ≈ `(0.24, 0.57, 0.45, 1)`, in ≈ `(0.55, 0, 0.76, 0.43)`
- exp1 (Rotate/Roll): out ≈ `(0.36, 0.50, 0.55, 1)`
- SineEase out: ≈ `(0.39, 0.58, 0.57, 1)`

Для пиксельно точной кривой (если захочется) — `CAKeyframeAnimation` c values из
формулы, шаг 0.1: expOut6 → y = 0 / 0.336 / 0.553 / 0.699 / 0.799 / 0.868 / 0.916 /
0.950 / 0.973 / 0.988 / 1.0. На практике bezier-аппроксимации визуально неотличимы.

### 3.3 Стоимость на A4 (главные риски)

- 3D-поворот полноэкранного слоя = 1–2 композитных слоя с perspective — GPU-SGX535
  тянет, но **каждый 3D-слой рендерится отдельно**; не пускать в поворот живые
  UIScrollView-и — на время перехода подменять снимком (`renderInContext:`) или
  прятать тяжёлых соседей (у нас уже так делает локскрин).
- Feather на 45 плитках = 90 CA-анимаций (transform+opacity) — ровно та ситуация,
  о которой предупреждает комментарий в MPTilesPageView.m:161. Ограничение:
  федерить только видимые (~24 на экране iPhone 4), ещё лучше — первые 12–16,
  остальным общий фейд; запускать раз в respring, не на каждый показ.
- Tilt — максимум 1 плитка под пальцем, дёшево (влиять на `layer.transform` напрямую
  в `touchesMoved`, без анимационного блока — как уже сделано в `updateCameraHint:`).
- Flip — 2 грани с preserve-3d, точечный слой — дёшево, но не флипать невидимые
  плитки (гейт видимости в MPLiveTileCenter уже есть).
- Весь экшен держим ≤ 0.35 с, без blur (Roll в WP не тащим — там честное размытие,
  на A4 дорого).

| Анимация | Точка входа | Что сейчас |

| Feather-въезд плиток | `MPHomeController.m:152–154` (`showMetroAnimated:`) | фейд всей вьюхи 0.25 с |

Пересмотр вопроса 118 (AUDIT-QUESTIONS-2, «turnstile дорого на iPhone 4»):
по числам тулкита turnstile — это всего ±80°/50° на 0.25–0.35 с; дорого он был бы
при анимации живой иерархии. Если анимировать снимок страницы (снимок делаем и так
в свитчере — `MPMultitaskView`), стоимость сопоставима со слайдом. Вывод: слайд
остаётся дефолтом, turnstile — осмысленный кандидат на «переключатель в настройках».
