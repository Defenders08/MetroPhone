## 1. ПРОЕКТ

**MetroPhone** — твик-оболочка Windows Phone 8.1 для iPhone 4 (iPod touch 4-го поколения в видео), iOS 6.1, theos, Logos/Objective-C, archs armv7+armv7s, минимум iOS 6.0. Theos в `~/theos`, SDK 10.3.

- Репо: `/Users/ash/Documents/Проекты/MetroPhone`. Код твика: `tweak/`. Deb: `builds/`.
- Сборка: `export THEOS=~/theos && make -C tweak package` — **СТРОГО ОДНОПОТОЧНО** (`make -j4` виснет). Из корня `make` пробрасывает в `tweak/`.
- Установка: **ТОЛЬКО USB** через `tools/dev.sh install <deb>` (iproxy + ssh-ключ `~/.ssh/iphone_rsa`, ControlMaster; Wi-Fi умер и не используется).
- Версии бампать в ДВУХ местах: `tweak/control` (строка Version) и `tweak/Tweak.xm:35` `#define MP_VERSION`. Перед каждым бампом ПЕРЕЧИТЫВАТЬ control — параллельные сессии правят дерево и бампают версии.
- Журнал твика на телефоне: `/var/mobile/Library/Preferences/metrophone.log` — единственный «глаз» (экрана мы не видим). Читать: `tools/dev.sh log 250`, чистить: `tools/dev.sh clearlog`.
- НЕ коммитить. НЕ трогать `AppDesigns/Clock/` (параллельные сессии правят Часы). Версию телефона смотреть: `tools/dev.sh cmd "dpkg -s ru.ash.metrophone | grep Version"`.

**Текущее состояние:** на телефоне **0.22.22**, код и телефон синхронны. Последний коммит в git — 0.22.3 (давно, всё не закоммичено, так задумано).

## 2. КЛЮЧЕВЫЕ КЛАССЫ И АРХИТЕКТУРА АНИМАЦИЙ

### Иерархия лаунчера
```
хост-окно SpringBoard (SBAppWindow, из хука SBWallpaperView)
└─ MPHomeController.view (root, чёрный фон, anchorPoint (0,0.5) — шарнир)
   └─ _pager (UIScrollView, 3 страницы)
      ├─ MPLiveWidgetsPageView (x=0, живые плитки)
      ├─ MPTilesPageView (x=320, «Start»: _scrollView → _headerLabel + MPTileView/MPLiveTileView)
      └─ MPAppListPageView (x=640, алфавитный список)
```

### Файлы анимаций
- **`tweak/MetroLauncher/MPAnimationConstants.h`** — ЕДИНАЯ точка всех длительностей/кривых/m34/таймаутов (`MPAnim*`). Здесь правится «движение» всего твика.
- **`tweak/MetroLauncher/MPHomeController.m`** (~900 строк) — вся логика переходов:
  - `playAppOpenAnimationForBundleID:pressedTile:launch:` — выезд при тапе по плитке; реальный `launch()` вызывается ТОЛЬКО в completion выезда, после него ставится «поза ожидания».
  - `playTurnstileOutWithCompletion:pressedTile:` / `playTurnstileIn` — Turnstile с **feather-стаггером по строкам** (углы +50° выезд / −80° въезд, шарнир каждой строки anchorPoint.x = −0.2 с компенсацией position, задержка `MPAnimFeatherStagger`=0.02 с на строку, тапнутая плитка уходит последней). Если строк нет (страница не собрана) — фолбэк: поворот целым слоем. Корень при feather НЕ вращается (под ним чёрный фон).
  - Completion — `[CATransaction setCompletionBlock:]` с `setAnimationDuration:total`; **анимации обязаны добавляться ВНУТРИ begin/commit** — пустая транзакция срабатывает при коммите и обрезает анимацию (журнал ловил это дважды: «запаздывание −182 мс», «−284 мс»).
  - Защита от гонок: `_turnstileGen` (инкрементируется в show/hide/play-методах; все completion проверяют gen, отсечённые зовут `mpFeatherCleanup`), `_animatingOpen` (глотает повторные тапы), `_enterInFlight` (въезд), `_deferEnterForLockscreen` (анлок ждёт сигнал), `_waitingPose` (поза ожидания), `_featherViews` (идемпотентная уборка шарниров/трансформов/opacity).
  - **Поза ожидания** (после выезда, до закрытия приложения): root виден ЧЁРНЫМ (identity, alpha 1), `_pager.hidden = YES`, касания выключены. Это закрывает родную сетку иконок SpringBoard (раньше поза была alpha 0 — сквозь неё просвечивал родной стол, видео это показало).
  - **Сторож запуска**: через `MPAnimLaunchWatchdog`=3.0 с после launch() проверяет `_pendingReturn`, `!MPHLauncherIsFrontmost` (окно приложения уже показалось → молчать) и `isRunning` через `SBApplicationController applicationWithDisplayIdentifier:` (тот же путь у свитчера). Не живо → `appWindowDidHide` → въезд сами. Для виджетов (bundleID=nil) — «страховка» 3.0 с: если SpringBoard всё ещё frontmost (UIWindow isFrontmost, категория MPFrontmost) → въезд.
  - Возврат из приложения: два сигнала — хук `SBAppWindow setHidden:` (Tweak.xm:~871, на iOS 6 при закрытии молчит) и **Home-фолбэк** в `menuButtonDown:` (Tweak.xm, задержка `MPAnimHomeFallbackDelay`=0.45 с) → `appWindowDidHide` → `playTurnstileIn`.
  - **Анлок**: `MPLockStateChanged` (Darwin `com.apple.springboard.lockstate`) → `showMetroAfterLockscreen` — подготовка сразу, а въезд по уведомлению **`MPMetroLockscreenDidHideNotification`** (постится из `MLSHideNow` в `MetroLockScreen/MPLockScreen.m` — единая точка скрытия локскрина), предел ожидания 1.0 с (`MPAnimLockscreenWaitCap`). Лок при открытом приложении: поза сохраняется вместе с `_pendingReturn`, лаунчер не мигает, возврат по Home работает.
  - `MPTurnstileInDidFinishNotification` (объявлена в MPHomeController.h) — «въезд доиграл»; на неё подписан Tweak.xm и делает **прогрев кэша приложений** (перенесён из таймера 0.5 с — он попадал в окно анимации и давал запаздывание completion 248 мс).
  - FPS-проба: CADisplayLink (`mpFpsStart/mpFpsStop:`) вокруг каждого перехода, строка `диаг fps[выезд/въезд]: N кадров, средний X мс, худший Y мс`.
  - `+metroTransitionActive` = `_pendingReturn || _animatingOpen || _enterInFlight`.
- **`tweak/MetroLauncher/MPTilesPageView.m`** — драйвер тапов/наклона: `tilesScrollTouchesBegan/Moved/Ended/Cancelled`, `cancelPress` (слоп 10 pt), `featherElements` (заголовок+плитки, отсортированы по y). Тап: `canLaunchWithBundleID:` (нет иконки — ни анимации, ни запуска) → `playAppOpenAnimationForBundleID:pressedTile:launch:`.
- **`tweak/MetroLauncher/MPTileView.m`** — tilt-нажатие: `pressTiltAtPoint:`/`releaseTilt`, ±6° (`MPAnimTiltMaxDegrees`), m34 на самой плитке, scale 0.97, opacity 0.92, доворот 0.08 с/возврат 0.2 с коротким CATransaction. Плюс «дыхание» плиток (CABasicAnimation `mpFloat`, repeat).
- **`tweak/MetroWidgets/MPLiveTileView.m`** — флип живой плитки: поворот к ребру 90° (0.2 с ease-in) → `renderReady` на ребре → модель в −90° при `setDisableActions` → возврат 0.2 с ease-out. Гварды: `_flipInFlight`, плитка нажата (transform ≠ identity), `[MPHomeController metroTransitionActive]` → renderReady без анимации. Лимит одновременных `MPAnimFlipMaxConcurrent`=3: лишние откладываются на 0.3–1.0 с (проверка ДО `_lastContent = content` — иначе повтор примут за «без изменений»). Счётчик `MPLiveFlipStarts` — массив временных меток с самоочисткой >1 с (вьюха, убитая посреди флипа, не блокирует флипы навсегда).
- **`tweak/MetroWidgets/MPLiveTileScheduler.m`** — тик 1 с; `setAnimPaused:` (пауза на переход/приложение — зовёт MPHomeController), `setDisplayOn:` (экран).
- **`tweak/MetroLockScreen/MPLockScreen.m`** — свой локскрин в окне нативного (SBAlertWindow), `MLSHideNow` постит сигнал анлока.
- **`tweak/AppDesigns/Settings/`** — дизайн Настроек; в `MPSettingsHooks.xm` метки таймингов и (`Tweak.xm`) хук `UIWindow makeKeyAndVisible` → `[MPSettingsTheme styleWindows]` — ранняя покраска окна в чёрный (белый прямоугольник при запуске Настроек побеждён; белый Default.png нативных приложений — НЕ наша власть).

## 3. ХРОНОЛОГИЯ ЭТОЙ РАБОТЫ (что сделали и почему)

1. **Разведка (0.22.12 на телефоне)**: все 5 анимаций уже были в коде (версии уехали от заявленных 0.22.9 из ТЗ). Найдено: `canLaunchWithBundleID` мёртвый код, completion через dispatch_after, Home-фолбэк с жёсткими 0.45 с, tilt↔флип пишут в один layer.transform, лимита флипов нет.
2. **Диагностическая 0.22.14** — только метки «диаг …» в журнал (дампы страниц в тап/launch, completion сработал/отсечён + запаздывание, фолбэк, lockstate, tilt, флип, Settings-тайминги). Прогон юзера: цепочка НЕ рвётся; дефекты из старого видео не воспроизводятся; найдены запаздывания completion до 248 мс, флипы по 2 за тик, въезд при анлоке играется ПОД локскрином.
3. **Сборка A (0.22.15–16)**: поза −80°/alpha 0 перед launch(); сторож 1.8 с (isRunning); CATransaction-completion; canLaunch; прогрев в completion въезда через NSNotification; страховка виджетов 3 с (isFrontmost); константы вынесены в `MPAnimationConstants.h`. Журналом подтверждено: сторож «пропущен (gen изменился)» = ровно один въезд.
4. **Сборка B (0.22.17)**: анлок по сигналу скрытия локскрина (предел 1 с); лок при открытом приложении сохраняет _pendingReturn; пауза живых плиток (setAnimPaused:); флипы: гварды + лимит 3. **Пойман и починен баг: в выезде анимации были вне транзакции → completion при коммите («запаздывание −182 мс», выезд обрезан на трети).**
5. **Сборка C (0.22.18)**: ранняя покраска окна Настроек (UIWindow makeKeyAndVisible → styleWindows). Тайминги: launch→ctor ~0.9 с (системный спавн), ctor→viewDidLoad ~1.2 с (PSListController, системное) — наши хуки лёгкие, оптимизировать нечего.
6. **Автономное доведение (0.22.19–20)**: реальный прогон поймал «сторож: Preferences не поднялось за 1.8 с» → таймаут поднят до 3.0 с + гвард frontmost. FPS-проба: 16.2–16.7 мс средний (~60 fps) → сделан **feather-стаггер по строкам**. Счётчик флипов стал самозалечивающимся.
7. **Фикс транзакций feather (0.22.21)**: в feather-версиях обоих методов анимации снова оказались вне транзакции (completion «−284 мс», въезд обрезан) — перенесены внутрь.
8. **Фикс просвечивания (0.22.22, по видео юзера)**: поза ожидания стала чёрной поверхностью (root alpha 1 + pager hidden, флаг `_waitingPose`) — раньше сквозь alpha 0 просвечивала родная сетка иконок SpringBoard во время системного launch-zoom и паузы 0.45 с перед въездом.
9. **Финальный прогон 0.22.22 (00:21)** — все критерии по журналу выполнены (см. §5).

## 4. ДИАГНОСТИКА: КАК ЧИТАТЬ ЖУРНАЛ

Метки (все с `MPLog`, префикс `диаг`), нормальные значения:
- `диаг[тап]` / `диаг[launch]` — дамп страниц пейджера; в launch root alpha=1.00 identity=1 (поза), раньше было alpha=0 (до 0.22.22).
- `диаг feather: выезд/въезд N строк, M элементов, всего X.XX с` — N строк ≈ 6–7, элементов 15, total 0.37–0.47 с.
- `диаг turnstileOut/In completion сработал t=… (запаздывание X мс)` — норма −10…+40 мс; до +350 мс при холодных возвратах (системная работа на main thread, рендер при этом ровный). **ОТРИЦАТЕЛЬНОЕ запаздывание = баг «пустой транзакции»** (анимации вне begin/commit).
- `диаг fps[выезд/въезд]: N кадров, средний X мс, худший Y мс (33.3 мс = 30 fps)` — норма 24–28 кадров, 16.4–17.0 мс средний, худший 20–33.
- `диаг сторож: пропущен (gen изменился …)` — норма на каждом возврате (сторож не дублирует въезд). `…не поднялось за 3.0 с → принудительный въезд` — крэш/отказ запуска.
- `страховка виджета: сработала` — URL-виджет ничего не открыл.
- `диаг wantsReturn=… waiting=…` — поза распознаётся.
- `диаг Home: фолбэк ЗАПУЩЕН/СРАБОТАЛ (0.45 с)` + `анлок: локскрин скрыт → въезд лаунчера` (анлок должен быть ПОСЛЕ скрытия локскрина; если сигнала нет — «въезжаем по пределу» через 1 с).
- `живые плитки: пауза/продолжение` — вокруг переходов.
- `диаг флип: начало (одновременно N) / конец` — N ≤ 3, парные.
- `диаг tilt: начало/возврат`, `диаг cancelPress` — на каждый тап (tap проходит через cancelPress — штатно).
- `диаг Settings: окно makeKeyAndVisible → ранняя покраска` должна быть РАНЬШЕ `первый PSListController viewDidLoad`.
- `=== MetroPhone 0.22.22 запуск (pid …)` — каждая версия пишет при старте процесса.

## 5. ЧТО ПОДТВЕРЖДЕНО / ЧТО ОСТАЛОСЬ

**Подтверждено журналами прогонов 0.22.21–22:** выезд/въезд feather 60 fps, completion точный, поза-чёрный закрывает родную сетку, анлок по сигналу, лок при приложении, сторож/страховка, флипы ≤2, tilt возвращается, прогрев после въезда, ошибок нет.

**Осталось вне твика (системное, честно объяснено юзеру):**
1. Системный launch-zoom iOS 6 — окно приложения растёт «из плитки» (глушить только рискованными приватными хуками SBUIController/SBAppWindow — селекторы не researched, НЕ делать вслепую).
2. Системный unlock-zoom — «двоение» при разблокировке.
3. Белые Default.png нативных приложений (Видео и пр.) при их запуске; превью/вёрстка самого приложения «Видео» — нативные.
4. Загрузка Glow Hockey — сама игра.
5. Вёрстка тумблеров Настроек (у края, мелкий текст) — дизайн-тикет, не анимации.

**«Призраки»/«двоение Start»/«плитки разного размера» на видео юзера (1 fps)** — кадры посреди feather-волны: строки на разных углах, перспектива меняет кажущийся размер. По fps-пробе в эти секунды ровные 16.4–17.0 мс. Это ожидаемый вид анимации, НЕ лаг.

**Техдолг:** диагностические метки «диаг …» в коде (дёшевы, полезны; снять отдельной сборкой по просьбе юзера). Позы ожидания на другом iPhone-размере не проверялись (только 320×480).

## 6. ГРАБЛИ (проверено болью)

- `make -j4` виснет — только однопоточно.
- `CATransaction setCompletionBlock` у ПУСТОЙ транзакции (анимации вне begin/commit) срабатывает при коммите → анимация обрезается. Всегда добавлять анимации ВНУТРИ транзакции.
- Приватные селекторы SB в .m без объявления интерфейса не компилируются (ARC/Logos): объявлять @interface-заглушки (примеры в MPHomeController.m: SBAwayController, SBApplicationController, SBApplication, UIWindow(MPFrontmost)).
- expect/Wi-Fi мертвы — только `tools/dev.sh` по USB; ControlMaster живёт 10 мин; если канал умер — `pkill -f "iproxy 2222"` и повторить, телефон может просто отвалиться от USB (бывало посреди установки — повторить install).
- Сессия юзера ведёт ПАРАЛЛЕЛЬНЫЕ сессии: перечитывать `tweak/control` перед бампом; не трогать Clock; не коммитить.
- uiopen на залоченном телефоне молчит; скрин-канал на локах отдаёт чёрный кадр 8214 байт.
- Часы телефона +1 ч к Mac — сверять по строкам журнала, а не по настенным часам.
- Отложенный applyContent виджета при переполнении лимита флипов: проверку лимита делать ДО `_lastContent = content`, иначе повторный вызов считается «без изменений».
- При правке поз/состояний лаунчера обновлять ВСЕ места распознавания состояния (wantsReturnFromApp, hide/showMetro, appWindowDidHide) — геометрическое «угадывание по alpha/hidden» уже приводило к рассинхрону, теперь флаг `_waitingPose`.
